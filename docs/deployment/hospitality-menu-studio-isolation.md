# Menu Studio staging exception to #181

18 November 2026 · Proposed for owner approval · [#181](https://github.com/derekfika/fika-os/issues/181) · [#586](https://github.com/derekfika/fika-os/issues/586)

Amend #181's staging project rule for **one** workload. Hospitality Menu Studio may run its synthetic hosted authoring stage in the exact owner-approved Firebase project `fika-menu-studio-dev`. Its single permitted application dependency outside the project is the existing staging Hub at `https://staging-os.fikacatering.com`, over HTTPS for Studio-specific AUTHMOD admission. Hub and every other FIKA staging workload retain their current projects and rules. This exception does not grant deployment, billing, IAM, DNS, AUTHMOD or cross-project workload access.

Use managed Firebase App Hosting with Studio-only build artifacts and a dedicated identity. App Hosting uses the same account for Cloud Build and Cloud Run. Artifact Registry's repository-level IAM makes the existing shared project unsuitable for this managed route. The dedicated account must have no direct access to shared staging or production resources. Apply the full #181 external-side-effect, data handling, policy verification and approval requirements. [Firebase environment isolation](https://firebase.google.com/docs/app-hosting/multiple-environments) · [App Hosting identity](https://firebase.google.com/docs/reference/apphosting/rest/v1beta/projects.locations.backends) · [Artifact Registry IAM](https://docs.cloud.google.com/artifact-registry/docs/access-control)

Allow authenticated Studio draft authoring in its dedicated named database only. Keep signing, publication, activation, commercial catalogue, booking, notifications, Workspace integrations and operational handoffs closed. The earlier Studio reader proposal concerned the older shared-project target. The new target's separate authoring grant requires explicit approval and covers named Studio draft transactions.

The old backend remains a historical provisioning record. It was observed with zero builds, rollouts and traffic, and its named database and account were verified to exist. No cloud evidence for the proposed new project is implied by that observation. Use the [hosted staging runbook](hospitality-menu-studio-staging.md) for provisioning and the first governed release.
