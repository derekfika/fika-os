## Backend extension (smallest, emulator-tested)
A **native collection movement can join a load-backed visit** by explicit visit id so both are ONE physical stop:
- `lib/types.ts` `DeliveryStop.visitId` is now also persisted for native stops joined to a visit.
- `lib/planning.ts` `combineStop`/`assignMovementStops`: optional `visitId` (new native stop carries it; joins an existing native stop with the same visitId; suppresses the "several visits" choice error).
- `app/api/logistics/route.ts` native `assign`: `visit` = `"new"` | visit id | `projection-visit:<id>`; the id is verified with `visitCandidates` against loads of the date (422 "That visit is not at this customer on this run." otherwise; transfers ignored).
- `lib/run-stop-order.ts` `physicalStops`: native stops with `visitId` merge into the visit's group (either id names it; naming both is refused).
- `lib/projection-dashboard-adapter.ts`: native stops get visit alias; native members of a visit named in the stored order stay on the run (this fixed a real bug found by the domain spec: the collection vanished from the chip after Save order).
Legacy placements without a visit id cannot be joined (they get a separate native stop) — documented limitation.
