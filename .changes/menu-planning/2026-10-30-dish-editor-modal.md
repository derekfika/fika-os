# 2026-10-30 — Create/Edit Dish modal with Enter-to-create (#154)

In the Week Planner dish picker, typing a name and pressing Enter now selects an exact existing dish (by name or alias, ignoring case and spacing) instead of duplicating it, and otherwise opens a **Create dish** modal prefilled with the typed name. The modal saves the canonical Dish Library record through the existing catalogue API (`create-dish`, which already matches an existing name or merged alias on the server) and assigns the saved canonical ID to the originating planner cell; Cancel, Escape and the close button save nothing and return to the same picker, query and cell. The old inline "create by name" request from the planner is removed. Each picker row also gets an **Edit** button that opens the same modal for an existing dish: it loads the full record and sends the current description, preparation notes, may-contain notes, subcategory, ingredients and method back unchanged, so an edit changes only name, primary category and tags (a save still moves the dish to `unreviewed`, as every dish edit already does).

The modal offers the governed primary categories, multi-select searchable tag checkboxes from the shared registry (#152), inline creation of a new tag, suggested tag chips from the dish name, a "similar dishes already exist" warning, a spelling warning that never blocks saving, a double-submit guard and error states. It never authors allergen evidence: a new dish starts with none and the CPU chef still checks and signs each release. `Dish` in the planner now carries optional `aliases`, `tagIds` and `subcategory` (for #155), and `useRollingData` exposes `refreshDishes`.

Salad slots (from the 30 Oct Salad Slot Tag Audit): the salad subtype stored in `subcategory` decides which planner salad slot offers a dish — SALAD 1 Leaf, 2 Slaw, 3 Starch, 4 Veg, 5 Grain/Pulse, 6 FIKA Seasonal — so a Leaf salad is offered only in the leaf slot, and so on; descriptive tags do not drive slots. Legacy "Salad N" values map to the same subtypes. Because no production dish has a subtype yet, a salad with no subtype stays offered in SALAD 1–5 (labelled "needs a salad slot") so no dish disappears before Brian classifies it; FIKA Seasonal is never inferred and SALAD 6 offers only dishes explicitly classified that way. The modal shows a "Salad slot" choice for Salad dishes; leaving it untouched on an edit keeps whatever is stored. No dish was reclassified or backfilled.

Not included: the optional collapsed provisional-allergen section (deliberately left out so no allergen state can be created by accident), the picker tag/category/salad-subtype filters (#155), and per-dish tag assignment of existing dishes. Existing planner entries keep their stored label after a dish is renamed.

Validation: Menu Planning typecheck, full suite (14 new tests), and governed validation; see the PR. Not checked in a browser (the local Menu app cannot load the planner without its authentication service) or on staging.
Deployment: none.
