# 2026-11-02 — Dish Library V2 archive-and-cutover tooling (#151)

Adds the tooling for the owner-approved "archive all of production V1, then activate validated V2 as the single active catalogue" strategy; it is tooling only and nothing has been run against staging or production. `lib/catalogue-cutover` provides a read-only `plan` (pre-state manifest, full raw archive set with digests, V2 active set, merge-only successor mappings, reference-integrity check, plan hash), a guarded `execute` (archive-first with readback, immutable sealed archive root using the #256 `referenceManifest` contract, activation in optimistic-concurrency batches on the catalogue manifest revision, resumable journal, never hard-deletes), `restore` (reproduces V1 documents and manifest content from the archive) and `verify` (counts, hashes, reference resolution through the #256 resolver). Production is refused unless `--execute`, `--allow-production`, `FIKA_CUTOVER_ALLOW_REAL_FIRESTORE=1`, a recorded `--approved-by` and an `--approval-hash` equal to the plan hash are all present. Frozen approved-proposal inputs, hashes and the runbook are under `apps/menu-planning/migrations/dish-library-v2/`.

Review fixes: execute refuses to resume when the live manifest moved on (journal aborted; restore or re-plan); restore reports post-cutover edits and new dishes, requires `--accept-post-cutover-changes`, preserves overwritten and created dishes under `postCutoverChanges/` (created dishes archived in place) and binds its approval hash to the live manifest revision and hash; duplicate active survivor names block the plan unless allow-listed (none today); verify no longer depends on exact-revision resolution after later edits; numeric fidelity checked on the emulator; the runbook requires a write freeze.

Validation: `npx tsx --test lib/catalogue-cutover/*.test.ts` passed, 42 tests (in-memory fake with transaction/precondition semantics); the same suite plus the real-adapter test passed against the Firestore emulator, 43 tests (demo project, no credentials); in-memory rehearsal on a V1 simulation derived from the staging export (542 docs, 353 active, 82/82 references, nine rolling ids active, restore byte-identical); `tsc --noEmit` passed.
Deployment: none; no staging or production reads or writes.
