# 2026-11-01 — Readable binary Hospitality allergen checker (#251)

The Hospitality order-detail "Digital master allergen checker" boxes are now strictly binary and text-free: click turns a named allergen ON (black, Contains) and OFF (white), identically by mouse, keyboard and touch. May Contain is no longer part of the click cycle in this view (the shared `applyHospitalityCellClick` used by other surfaces is unchanged); a persisted May Contain is preserved verbatim, shown hatched with no glyph, and only changes when the chef deliberately clicks that box, which turns it into Contains (the stricter value, never a silent deletion; a second click turns it OFF). Notes are left intact. "No Key Allergens" is now the same white/black box (no checkbox, label or status in the cell), still a deliberate chef declaration, mutually exclusive with named allergens; turning the last allergen OFF leaves the row blank/unverified, never No Key. Each box is a native button with a non-visible accessible name (allergen, row, on/off) and `aria-pressed` (`mixed` for a legacy May Contain), with a visible focus ring and 44px touch targets. The review warning stays in the Check column; the helper text no longer describes the old white/contains/MC cycle. Layout: wider name, notes and Check columns, a sticky dish-name column and horizontal scroll inside the checker, purple heading row and paper order unchanged.

No change to stored allergen values, the canonical contract, #225 attestation/pending-materialisation gates, signing, hashes or migrations; any click still reopens the row's review (and revokes via the existing paths). Blank rows still cannot be checked, signed or released.

Validation: new state-machine, exclusivity, blank-not-clear, legacy May Contain, accessibility-attribute and source-shape tests in `hospitality-allergen-review.test.ts`; CPU `typecheck` and `npm test`. No browser viewport run yet (820/1024/1280/1536px) — still to be done on authorised staging.
Deployment: none.
